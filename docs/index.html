REPE Remote Efficient Protocol Extension

A fast and simple RPC protocol that can package any data format and any query specification behind a fixed 32-byte binary header.

Explore the Header View the Spec

  • Easy to use

struct header {
  uint16_t spec{0x1507};  // REPE magic
  uint8_t  version{2};      // protocol version
  uint8_t  flags{};         // bit 0: notify
  uint32_t ec{};            // error code
  uint64_t id{};            // request id
  uint64_t body_length{};   // body bytes
  uint32_t query_length{};  // query bytes
  uint16_t query_format{};
  uint16_t body_format{};
};  // exactly 32 bytes

    spec: u16,          // REPE magic (0x1507)
    version: u8,        // protocol version (2)
    flags: u8,          // bit 0: notify
    ec: u32,            // error code
    id: u64,            // request id
    body_length: u64,   // body bytes
    query_length: u32,  // query bytes
    query_format: u16,
    body_format: u16,
}  // exactly 32 bytes
Why REPE

One header. Any payload. Any query.

REPE defines a compact binary header and gets out of your way. The body can be JSON, BEVE, raw binary, or text — and the query can use whatever specification fits your system.

⚡

High performance

A fixed, naturally-aligned 32-byte header with no padding. Little-endian by design for optimal throughput on modern hardware.

🧩

Format agnostic

The body carries any format you like. Tag it with a body_format code — JSON, BEVE, UTF-8, or raw binary — and parse accordingly.

🔎

Query agnostic

Address data however you want. Use JSON Pointer, raw binary, UTF-8, or a custom query specification of your own.

↔️

Symmetric messages

Requests and responses share the exact same layout. Receivers distinguish them by context — no separate framing to learn.

🪶

Trivial framing

No total-length field needed. Read 32 bytes, then query_length + body_length bytes. That's the whole message.

🔀

Async by design

Every message carries a 64-bit id, so responses match their requests and many calls can stay in flight on one connection. Flip the notify flag for one-way, fire-and-forget sends.

The Header

32 bytes

Every field has a fixed offset and size. Hover or tap a field to highlight it in the byte map. Recognize REPE from just the first three bytes: the spec magic followed by the version.

FieldTypeOffsetBytes
Message Layout

Header · Query · Body

A REPE message is three contiguous parts. The query and body are optional — set their length to zero to omit them entirely.

Header 32 bytes · fixed
Query query_length bytes
Body body_length bytes

total length = 32 + query_length + body_length

Formats

Reserved format codes

Values 0–4095 are reserved for the REPE specification. Custom formats should use values above 4095.

Error Codes

A defined error vocabulary

The error code lives in the header's ec field; an optional UTF-8 message lives in the body. Codes 0–4095 are reserved for REPE; applications use 4096 and above.

CodeMessageMeaning
0OKNo error
1Version mismatchMismatching REPE version
2Invalid headerThe REPE header was invalid
3Invalid queryThe query was invalid
4Invalid bodyThe body was invalid
5Parse errorAn error occurred while parsing the data
6Method not foundThe method does not exist or is not available
7TimeoutTimeout
Implementations

Use REPE from your language

Production libraries already speak REPE. Both currently target the v1 wire format and are updating to v2 — the layout documented across this site.

C++

Glaze

stephenberry/glaze ↗

REPE ships inside Glaze, a high-performance C++ JSON/BEVE library. Bodies serialize straight from your structs — no hand-written glue.

  • JSON & BEVE bodies, reflected directly from C++ types
  • Registry to expose functions and objects as endpoints
  • JSON Pointer queries into registered state
  • Built-in REPE ⇄ JSON-RPC conversion
  • Header-only, with asio networking examples
#include <glaze/rpc/repe/repe.hpp>

Rust

repe-rs

repe-org/repe-rs ↗

The repe crate: a full async-capable REPE stack with clients, servers, routing, and multiple transports.

  • Sync & async (tokio) clients and servers
  • JSON (serde) & BEVE bodies, zero-copy message views
  • Multiplexed requests, timeouts, batching, notify
  • Dynamic Registry routing with JSON Pointer
  • Fleet multi-node TCP/UDP fanout
  • WebSocket transport (native + wasm browser client)
  • Backpressure streaming with reconnect-resume · repe CLI
cargo add repe
